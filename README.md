# 台灣股市投資組合自動追蹤系統 (Gmail 版)

這是一套整合了 TWSE OpenAPI、yfinance、SQLite、Matplotlib 與 GitHub Actions 的全自動化投資組合追蹤工具。

## 為什麼選擇 Gmail？
相較於通訊軟體 (LINE、Telegram、Discord)，Email 是最穩定、最不依賴第三方平台 API 的終極解法。本系統使用 Python 內建函式庫，自動生成精美的 HTML 表格，並將資產走勢圖內嵌於信件中，每天自動寄送到你的信箱。

## 如何部署 (免伺服器教學)
1. **建立專案**：將此 ZIP 解壓縮後的所有檔案，上傳至你的 GitHub Private Repository (私人儲存庫)。
2. **申請 Gmail 應用程式密碼 (App Password)**：
   - 登入你的 Google 帳號，前往 **「管理你的 Google 帳號」**。
   - 選擇左側選單的 **安全性 (Security)**。
   - 確認你已經開啟 **兩步驟驗證 (2-Step Verification)**。
   - 在搜尋列搜尋 **「應用程式密碼 (App passwords)」**。
   - 建立一個新的應用程式名稱 (例如 "Portfolio Tracker")，系統會產生一組 **16 位數的英文字母密碼**，請複製下來。
3. **設定 GitHub Secrets**：
   - 到你的 GitHub Repo，點選 **Settings > Secrets and variables > Actions**。
   - 新增第一個 Secret，名稱為 `GMAIL_ADDRESS`，填入你的 Gmail 信箱 (例如 `yourname@gmail.com`)。
   - 新增第二個 Secret，名稱為 `GMAIL_APP_PASSWORD`，貼上剛才產生的 16 碼應用程式密碼。
4. **給予 Action 寫入權限 (為了更新 SQLite 資料庫)**：
   - 到 Repo 的 **Settings > Actions > General**。
   - 在 **Workflow permissions** 區塊，勾選 **Read and write permissions** 並儲存。
5. **啟動排程**：
   - 系統已設定為 **每週一到週五的台灣時間下午 17:30** 自動執行。
   - 你也可以在 GitHub Repo 的 **Actions** 頁籤中，點選「Daily Portfolio Tracker」，手動按下「Run workflow」來立即測試，你的信箱馬上就會收到報表！

## 本次更新：估值邏輯強化

針對「本益比法／淨值比法用固定價格門檻判斷停利，無法區分『剛過線一點點』跟『歷史級噴出』」的問題，做了以下強化：

1. **歷史百分位判斷**（`valuation_engine.py`）
   `calc_pe_valuation` / `calc_pb_valuation` 現在會多回傳一個值：現在的本益比／淨值比，落在近 5 年歷史資料的第幾百分位。價格門檻（便宜價/合理價/目標價）的計算方式不變，但判斷「是否為統計異常」改用百分位，不受個股股價絕對水位影響。

2. **營收動能交叉驗證**
   新增 `get_revenue_momentum()`，比對最新月營收年增率是否比 3 個月前更快。當估值百分位超過 `portfolio_config.py` 裡的 `EXTREME_VALUATION_PERCENTILE`（預設 95）時，會再檢查營收是否同步加速（`MOMENTUM_YOY_THRESHOLD`，預設年增 20%）：
   - 估值破新高 **且** 營收同步加速 → 🟣 標記為「結構性重估中」，提醒這不是一般的停利訊號。
   - 估值破新高 **但** 營收未同步加速 → 🔴 標記為更嚴格的警示，慎防情緒推升。
   - 沒有落在極端百分位（例如剛好過線一點點的個股）→ 維持原本的燈號邏輯，不受影響。

3. **個股質化備註欄位**（`portfolio_config.py` 的 `note` 欄位）
   讓模型看不到的質化風險（法律訴訟、合併綜效、ETF報酬結構與殖利率脫鉤等）可以直接附註在對應個股上，並顯示在信件的狀態欄位下方。

4. **資料抓取異常警示**
   所有 API／備援抓取的例外現在都會被收集到 `self.fetch_errors`，並在 email 最上方顯示黃色警示條，避免把「資料抓不到」誤讀成「模型判斷為觀望」。

5. **FinMind API 輕量快取**
   歷史 PER/PBR/月營收資料現在會快取進 `portfolio_history.db` 的 `finmind_cache` 表，預設 7 天內不重複抓取，降低免費額度用量，也讓 API 短暫異常時仍有舊資料可用。

> 以上調整僅供輔助判斷，不構成投資建議；`EXTREME_VALUATION_PERCENTILE` 與 `MOMENTUM_YOY_THRESHOLD` 兩個門檻都可以在 `portfolio_config.py` 依個人風險偏好調整。

## 再次更新：金融股與記憶體股改用現金殖利率法

原本用「淨值比法」評估的兆豐金、玉山金、台中銀、台企銀、永豐金，以及南亞科、華邦電，全部改用跟敦陽科／創見一樣的「去年現金配息率 × 今年預估EPS」現金殖利率法：

- `payout_ratio`：取自各股 **2025 年度**實際發放的現金股利 / EPS（例如兆豐金 1.75÷2.36≈74%）。
- `estimated_eps`：金融股用最新累計季報年化粗估；南亞科、華邦電採用 FactSet 法人共識中位數（2026 年約 40 元 / 21 元）。

> ⚠️ 這兩個數字都是粗略估計，尤其記憶體雙雄的法人預估區間很寬（華邦電 12.82～25.54 元），建議每季財報公布後手動更新 `estimated_eps`，不要長期沿用同一個數字。
>
> ⚠️ 副作用：改用殖利率法後，這 7 檔不再套用先前的「歷史百分位＋營收動能」交叉驗證（該邏輯目前只接在本益比法／淨值比法的分支），改回跟敦陽科一樣的單純殖利率門檻判斷。如果之後想要，殖利率法也可以比照做「現在殖利率落在近5年歷史第幾百分位」的判斷，需要另外抓歷史殖利率序列，目前版本還沒做這塊。

## 再次更新：預估EPS改為自動抓取，不用手動維護

`estimated_eps` 現在有了自動版本，不用每季手動改數字：

- 新增 `valuation_engine.py` 的 `get_annualized_eps()`：抓 FinMind「綜合損益表」(`TaiwanStockFinancialStatements`) 的季度EPS，把**今年至今已公布的季報EPS加總**，再依「已公布幾季」年化推算全年（例如只公布上半年2季，就用「上半年累計 x 2」；公布3季就用「前3季累計 x 4/3」）。今年還沒有任何季報時（通常1月初），自動退回去年整年EPS加總。
- `portfolio_config.py` 裡的 `estimated_eps` 現在是**選擇性覆寫**：留空/設0 → 自動年化；手動填數字 → 優先用手動值，蓋過自動計算。
- 兆豐金、玉山金、台中銀、台企銀、永豐金、敦陽科都已經拿掉手動 `estimated_eps`，改用自動年化。
- 南亞科、華邦電**保留**手動設定的 FactSet 法人共識中位數（約40元／21元），因為這兩檔是記憶體循環股，獲利加速度很快，機械式「上半年 x 2」年化容易低估接下來幾季的成長；如果你想改成完全自動，把這兩檔設定裡的 `estimated_eps` 欄位刪掉或設成 0 即可。

> ⚠️ 已知限制：如果公司當年度配發股票股利（無償配股），依規定要追溯調整加權平均股數，但 FinMind 的季度 EPS 存的是各季公布當下的原始值、不會回頭改寫。台中銀、台企銀這種偏好配股票股利的银行，年度中間配股後，用本函式加總可能會有小幅高估，這是資料源的限制，不是程式邏輯錯誤。

## 再次更新：南亞科、華邦電也改用自動年化EPS，不再用法人共識

原本這兩檔手動填了 FactSet 法人共識中位數（南亞科40元、華邦電21元），現在拿掉了，改成跟其他殖利率法個股一樣，用 `get_annualized_eps()` 自動抓最新公布的季報年化：

- 南亞科：2026上半年(Q1 8.41 + Q2 14.66)累計23.07元，年化(x2)= **46.14元**，比原本手動的40元更高，換算下來目標殖利率狀態從「🟡偏高」變成「🔵合理」。
- 華邦電：2026上半年(Q1 2.25 + Q2 5.40)累計7.65元，年化(x2)= **15.3元**，比原本手動的21元低不少，換算下來狀態從「🔵合理」變成「🔴達標(停利)」。

> ⚠️ 兩檔的方向不一樣：南亞科用自動年化後看起來更「合理」，華邦電卻變成「達標」，這剛好說明法人共識跟機械式年化本來就會有落差——法人的21元可能已經把下半年更強的成長性算進去，機械式年化只會看已經發生的數字。哪個比較準沒有標準答案，但既然你想要「以實際公布數字為準」，現在系統就是照這個邏輯跑，之後每次新一季財報出來就會自動更新，不用再手動改。

## 再次更新：目標殖利率門檻也改為自動計算

殖利率法(`yield`)跟目標殖利率法(`etf_yield`)裡的「便宜/合理/目標殖利率」門檻，原本全部都是人工設定的整數（例如敦陽科的6%/5%/4%），不管是原本 repo 就有的還是我後來手動抓的，都不是程式算出來的——這是全系統裡最主觀、最沒有經過驗證的一塊。

新增 `valuation_engine.py` 的 `calc_yield_percentile_bounds()`：直接複用抓 PE/PB 百分位時已經拿到的 `TaiwanStockPER` 資料集（裡面本來就有 `dividend_yield` 欄位，不用多打一次API），取近5年歷史殖利率的第80/50/20百分位，分別當作便宜/合理/目標門檻（殖利率越高越便宜，所以用80百分位當便宜門檻，跟PE百分位的方向相反）。

`portfolio_config.py` 裡的 `target_yields` 現在也是**選擇性覆寫**：
- 留空（不寫這個欄位）→ 自動抓近5年歷史殖利率百分位。
- 手動填 `{"cheap":.., "fair":.., "target":..}` → 優先用手動值。

目前全部 14 檔用到殖利率法的標的（敦陽科、兆豐金、玉山金、南亞科、華邦電、創見、台中銀、台企銀、永豐金、富邦台50、國泰永續高股息、富邦科技、元大台灣50、元大高股息）都拿掉了手動門檻，改成自動計算，每檔股票用自己的歷史脾氣校準，不再套用同一套人工目測的整數門檻。

> ⚠️ 提醒：富邦台50、元大台灣50、富邦科技這三檔的備註仍然保留「殖利率法僅供參考」的警語——不管門檻是自動算的還是手動設的，用殖利率去評估一檔報酬主要來自資本利得的市值型ETF，方法論本身的侷限都還在，自動化只解決了「門檻怎麼訂」的問題，沒有解決「這個方法適不適合這檔標的」的問題。

## 再次更新：股票股利改為附註參考，不併入現金殖利率估值

金融股（尤其台中銀、台企銀）除了現金股利，還會配發股票股利。股票股利本質上是保留盈餘轉股本、配發新股給股東，公司總市值不會因此改變（除權參考價會同步往下打折），跟現金股利「公司現金真的變少、股東真的拿到錢」性質不同，所以**沒有**把它直接加進現金殖利率、套用同一組目標殖利率門檻去反推便宜/合理/目標價——那樣會系統性高估真實的現金報酬。

改成新增 `valuation_engine.py` 的 `get_stock_dividend_info()`：自動抓最近一次股利政策公告(`TaiwanStockDividend`)的股票股利金額，換算成「含股票股利的總配發率」，附註顯示在狀態燈號下方，例如：

> 另有股票股利0.67元(約當年增股數6.7%，未列入殖利率估值)；含股票股利的總配發率約69.3%

這樣可以同時看到「現金殖利率估值」（決定便宜/合理/目標價）跟「總配發率」（了解公司實際上把多少比例獲利以某種形式還給股東）兩個獨立資訊，不會互相污染。
